Parse

Read every pattern result from fail_die_1.log

For each pattern id, count fails, passes, and failing channels.

  • Log labels are 1-based (P1…P1000)
  • Dashboard ids are 0-based (0…999) — tool maps Pn → id n−1
  • Fail = any channel line with STATUS:F for that pattern
  • If one channel failed, the whole pattern is failed on that die
Real example from this file — pattern P8
CH1 and CH2 are STATUS:P. CH3 is STATUS:F.
Rule: if any one channel fails, the whole pattern is counted as failed on that die (we do not count CH1/CH2 as pattern passes).
So: fails = 1, passes = 0, fail rate = 100%, failing channel = CH3.
Dashboard id = P7 (because log P8 → id 7).

That 100% means “failed on this die,” not “fails on every die forever.”
Counts measured on this file: 1000 patterns with status · 57 failing · 943 pass-only

Run next

Failed on fail_die_1 → include

Every pattern with at least one STATUS:F is recommended for the next die.

  • This file: 57 failing labels (log P8, P18, P44, P71, … P967)
  • Dashboard ids: P7, P17, P43, P70, …

3b
Skip next

Only passed on fail_die_1 → skip

Patterns with fail = 0 and pass > 0 are not recommended for the next die.

  • This file: 943 pass-only patterns
  • This is where test-time reduction comes from
  • Evidence-based: the log said they passed on this die
Meaning: no fail evidence → skip them next to save ATE time
then order the 57 failers
4
Order

Rank failed patterns by severity

With one die log, order by how hard each pattern failed on that die.

  • 1st: more failing channels
  • 2nd: higher fail rate
  • 3rd: more fails
  • On fail_die_1.log, many failers look alike: 1 channel (often CH3), 100% rate, 1 fail — so they are near ties
Why fail rate is 100% here
One die: fail rate = 1 ÷ (1 + 0) = 100% for every failer. That is expected for a single-die Advantest log like this one.
